# Анализ проекта «Проект V2»

Дата анализа: 11.11.2026 · Источник: `/Users/temp/Desktop/Проект V2`

## 1. Что это

Внутренняя система управления швейным производством: цех (заказы на пошив, крой, этапы, зарплата), склад (остатки, приход, адреса, отгрузки), магазин (корзина, продажи) и интеграция с Wildberries (FBS-заказы, кабинеты, синхронизация). Работает на одном Mac в локальной сети; клиенты — браузер (PWA), два Android-приложения и голосовой ассистент.

## 4. Сильные стороны

1. **Продуманный домен**: единые статус-машины, маршруты этапов с зависимостями, идемпотентность (`external_uuid`), трассировка до строк Excel (`source_sheet:source_row`).
2. **Дисциплина бэкапов**: ежедневные снапшоты (`backups/2026-*`), бэкап книги перед записью, мастер-копия с sha256, режим 444.
3. **Реальный офлайн**: PWA-склад работает без сети с очередью операций и синхронизацией.
4. **Тесты есть и растут**: 93 функции — заказы, сборка FBS, роли, сессии, импорт/экспорт.
5. **Документация честная**: ТЗ, дизайн миграции, отчёт о росте с самокритикой.

## 5. Риски и проблемы

### Критичные

1. **Excel как источник истины** — главная хрупкость: конкурентная запись через файловые блокировки, отрицательные остатки, книга в облаке. SQL-миграция спроектирована, но застыла на фазе 2 (теневой режим выключен).
2. **Монолиты**: `cex_api.py` — 4 587 строк с диспетчеризацией через цепочку `if path == ...`; `app.js` — 204 КБ. Изменения дорогие и рискованные.
3. **Собственный HTTP-слой** на `BaseHTTPRequestHandler`: ручной разбор cookie/сессий, нет CSRF-защиты, TLS — самоподписанный (`tls_cert.py`). Для LAN допустимо, но любой выход наружу опасен.

### Средние

4. **Мусор в репозитории**: 15+ `.bak`-файлов рядом с исходниками (`cex_api.py.*.bak`, `app.js.*.bak` — по 100–240 КБ), временные Excel-локи (`~$*.xlsx`), zip на 83 МБ в корне.
5. **Секреты и их границы**: `keystore.jks` лежит в git, пароль `ceh2026` записан в документации — ключ подписи APK фактически скомпрометирован внутри команды.
6. **Работа вне git**: фича «голосовой ассистент» (6 файлов) не закоммичена; 26 изменённых файлов висят с 08.11.
7. **Двойное хранение заказов**: JSON-реестр магазина + SQLite + Excel-отчёты WB — без сверки расходятся (уже были инциденты: дубли 72 вместо 58).

### Низкие

8. Старый отчёт о росте (06.11) фиксировал 40 тестов — сейчас 93: тестовая база растёт быстрее документации.
9. `logo.png` — заглушка 1×1 px; логотип подставляется из настроек.

## 6. Рекомендации (по приоритету)

1. **Закоммитить текущую работу** — отдельными коммитами: ассистент, изменения склада/WB.
2. **Убрать `.bak` из корня** в `backups/code/` (или удалить — есть git).
3. **Включить shadow-режим SQL** и еженедельную сверку `compare.py` — это уже построено, осталось включить; иначе миграция на SQL не сдвинется.
4. **Разбить `cex_api.py`** по доменам: заказы / крой / маршруты / снабжение / доступы (по границам, которые показал graph-отчёт).
5. **Сменить ключ подписи APK** или хотя бы убрать пароль из README и `keystore.jks` из git-истории.
6. **Не трогать**: стек SQLite-вместо-PostgreSQL и WebView-обёртки — для 2–3 пользователей решения адекватные, менять их сейчас вредно.
